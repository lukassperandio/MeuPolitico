# MeuPolítico Design

## Mode
Operate — scanability first.

The interface should feel like a serious public-data product:
clear, trustworthy, restrained and information-dense without feeling cramped.

Prioritize:
1. Information hierarchy
2. Scanability
3. Readability
4. Consistency
5. Visual polish

## Do

### Typography
- Use a clear typographic hierarchy between page titles, section headings, body text, metadata and labels.
- Inter is allowed as the primary UI font.
- Do not use typography as decoration.
- Use tabular numerals for financial values, counts and statistics.
- Use monospace sparingly and only when it improves data readability.

### Color
- Primary: deep blue (#0B3D62 range)
- Accent: green (#0F9B6C range)
- Backgrounds: off-white / soft gray-green
- Text: dark neutral rather than pure black
- Borders: subtle neutral tones
- Use color primarily to communicate meaning, state and hierarchy.
- Green should communicate positive/transparency-related states, not decorate the interface.
- Red should be reserved for destructive actions and negative states.

### Surfaces
- Prefer flat surfaces with subtle borders.
- Cards should use one visual elevation level at most.
- Use restrained border radius: approximately 6–10px.
- Avoid excessive shadows.
- Avoid nested cards whenever possible.
- Use whitespace and borders to establish hierarchy instead of shadows.

### Layout
- Use a consistent spacing system.
- Prefer strong alignment and predictable grids.
- Keep content widths controlled rather than stretching everything across the screen.
- Prioritize horizontal alignment of labels, values and actions.
- Tables and lists should feel dense enough for efficient scanning while remaining comfortable to read.

### Tables & Data
- Tables are a primary UI pattern, not an afterthought.
- Align numerical values consistently.
- Use tabular numerals for money, counts and percentages.
- Keep column headers visually distinct but restrained.
- Avoid excessive row decoration.
- Use hover states subtly.
- Make important values easy to find without turning every value into a colored badge.

### Components
- Buttons should be compact, clear and purposeful.
- Primary actions should use the deep blue primary color.
- Secondary actions should rely on neutral surfaces/borders.
- Inputs should be simple and highly readable.
- Badges should be used only when they communicate meaningful state or classification.
- Icons should support recognition, not decorate every piece of information.

### States
- Empty states should be useful and concise.
- Loading states should be minimal and unobtrusive.
- Error states should clearly explain what went wrong and what the user can do.
- Source notes and attribution should remain visible but visually secondary.

### Motion
- Use animation only when it communicates state or improves orientation.
- Prefer short, subtle transitions.
- No decorative motion.

## Don't — AI Slop

- No purple-to-blue gradients.
- No glassmorphism.
- No neon colors.
- No glowing elements.
- No decorative orbs.
- No excessive blur.
- No oversized rounded cards.
- No cards nested inside cards.
- No excessive pill-shaped UI.
- No random gradients.
- No excessive shadows.
- No colorful icon containers everywhere.
- No colored side-tabs on every card.
- No animation without functional purpose.
- No huge hero sections for ordinary application screens.
- No excessive use of badges.
- No gray text on colored backgrounds when contrast is weak.
- Do not make every section visually prominent.
- Do not use color where typography, spacing or structure would communicate better.

## Brand Anchors

- Primary: deep blue (#0B3D62 range)
- Accent: green (#0F9B6C range)
- Surfaces: off-white / soft gray-green
- Numbers: tabular numerals
- Overall impression: trustworthy, civic, modern and data-oriented.

## Design Principle

The interface should look like a real public-data platform, not an AI-generated SaaS dashboard.

When choosing between visual decoration and information clarity, always choose information clarity.
